# Double Life — M1

Roblox-прототип взаимодействия гостей, персонала, NPC-охраны и владельца. Продолжение M0 из `feat/m0-playable-slice`, а не готовая игра или полный особняк. Концепция: [docs/CONCEPT.md](docs/CONCEPT.md).

## Запуск

Нужны Roblox Studio и Rojo CLI (проверено с 7.7.1).

```sh
rojo build default.project.json -o DoubleLife.rbxlx
```

Открыть файл в Studio. Для совместного теста выбрать **Test → Start Test Session → Server and Clients** (F7), выставить 2–5 клиентов. В новых версиях Studio можно запустить сервер и добавить клиентов через кнопку **Add Clients**. Альтернатива: `rojo serve default.project.json`, затем подключить плагин Rojo к этому проекту.

Роли назначаются по фактическому порядку подключения, который не всегда совпадает с номером окна Studio: владелец, шпион, контрразведчик, персонал, гость. Смотрите свою роль в HUD. Скрытые роли других игроков не отправляются клиенту, не записываются в атрибуты или Teams. Предсказуемый порядок — ограничение тестового состава, не финальный способ распределения.

## Механики

- **M0 сохранён:** открытие двери владельцем, боковое окно шпиона, сейф, досье, главный выход, приватное чтение журнала контрразведчиком, три картины для всех. После выноса досье сброс через 8 с; смерть/сброс персонажа/уход носителя возвращает досье в сейф.
- **Один охранник:** серверный `Patrol → Investigate → Return → Patrol`. Стартует в коридоре, реагирует на разбитый бокал, вскрытое окно и начало доставки. Бездействие или уход владельца не останавливает патруль. NPC идут по пути через Humanoid; телепортаций для восстановления нет.
- **Приказы:** у пульта в коридоре E открывает кабинет на 20 с; Z переключает патруль между холлом и коридором; X отправляет проверить кабинет. Z/X имеют общий кулдаун 25 с и принимаются только в патруле. При проверке кабинета дверь остаётся открыта достаточно долго для возвращения.
- **Публичные запросы:** у двух зелёных столиков E заказывает безалкогольный сок именно к этому столику. Действие одинаково для гостя, шпиона и остальных ролей. Один активный запрос на игрока, кулдаун 45 с, срок 90 с, не более 8 заказов одновременно.
- **Персонал:** у стойки в северо-западной части холла E принимает старейший чужой заказ, повторное удержание E берёт сок. Поднос виден в мире. У нужного столика F завершает доставку и даёт 10 очков только за текущую сессию. Очки не сохраняются, повторная доставка не начисляет награду, собственный заказ выполнить нельзя.
- **NPC-помощник:** через 8 с берёт непринятый заказ, физически идёт от стойки к столику и обратно. Выполняет по одному заказу и не создаёт очков. Если персонал ушёл или сбросил персонажа, заказ возвращается в очередь; если ушёл заказчик — отменяется.
- **Отвлечение ограничено:** проверка до 18 с, затем возврат до 18 с и обязательные 12 с патруля. Источник шума повторно принимается не чаще 45 с; новые события не продлевают активную проверку и не прерывают возврат. Бокал восстанавливается через 45 с, окно нельзя продлевать спамом.
- **Следствия в мире:** осколки бокала, следы на раме окна, сок на столике, изменившийся сейф, поднос и перемещение NPC. Кража не вызывает общей тревоги или подсветки виновного. Общее сообщение M0 появляется только после успешного выхода с досье.

Все игровые изменения делает сервер. Он проверяет роль, живого персонажа, дистанцию, прямую видимость, доступность подсказки, минимальное время удержания и кулдауны. Клиент не сообщает «доставка выполнена» или «досье украдено». Нет постоянной валюты, убийств, исключения из игры, платных преимуществ и обязательного общения.

## Проверка для 2–5 игроков

Подробный маршрут, негативные проверки и точные ожидаемые состояния: [docs/M1_TESTING.md](docs/M1_TESTING.md). Результаты фактически выполненных проверок: [docs/M1_VALIDATION.md](docs/M1_VALIDATION.md).

| Состав | Что проверить |
| --- | --- |
| 2: владелец, шпион | Заказ шпиона → доставка NPC → уход охранника из коридора → окно → сейф → выход. Повторить с бездействующим владельцем. |
| 3: +контрразведчик | Перед выходом шпиона осмотреть сейф/журнал вручную. Другие клиенты не получают извещения о краже. |
| 4: +персонал | Персонал принимает заказ до NPC, берёт сок на стойке и доставляет; проверяет +10 очков, повторную доставку, сброс персонажа/уход. |
| 5: +гость | Гость и шпион пользуются одними столиками. Проверить очередь, лимиты и отсутствие чужих ролей в UI. |

## Автоматические проверки

```sh
luau tests/run.luau
luau-analyze src/server/GuardPolicy.luau src/server/RequestLedger.luau tests/run.luau
rojo build studio-tests.project.json -o DoubleLife-tests.rbxlx
```

`tests/run.luau` — 46 проверок политики охранника и жизненного цикла заявок. Каждый `.luau` можно проверить командой `luau-compile --null <файл>`.

Отдельный тестовый мир запускает движковые проверки пути, доставки, восстановления и клиентскую проверку приватности. Затем проходит через настоящие ProximityPrompt с 2–5 клиентами. Ждите `M1 STUDIO SUITE PASS` и `M1 PLAYTHROUGH PASS` в Output сервера, а на клиентах — `M1 CLIENT AUDIT PASS`. Тестовый сценарий переставляет **игроков** к объектам для воспроизводимости; NPC продолжают идти физически. Это не заменяет ручной проход маршрута пешком. `M1TestDriver` существует только в тестовой сборке; `default.project.json` не включает тесты.

## Архитектура и ограничения

`Game` связывает `World`, `Roles`, `Interactions`, `Dossier`, `WorldEvents`, `GuardService`/`GuardPolicy`, `NpcMover` и `Requests`/`RequestLedger`. Только HUD и общие константы реплицируются клиенту. Серверная логика заявок и ограничений отделена от Roblox API для повторяемых тестов.

Pathfinding ограничен двумя попытками, 3 с на расчёт/точку и общим сроком действия. Заблокированный путь пересчитывается; охрана пробует точки маршрута и последнюю достигнутую позицию. При полной физической изоляции NPC продолжает попытки после тайм-аута — не проходит сквозь стену. NPC и игроки не сталкиваются друг с другом и не перекрывают единственный проход.

Геометрия и NPC остаются простыми Part, без анимаций и звуковых ассетов. Охранник пока наблюдатель: задержаний, допросов и автоматического обнаружения шпиона нет. Заказ отвлекает охранника только когда тот готов принять событие; это возможность, не гарантированный обход. Полноценные раунды, случайные роли, баланс, проверки сетевого перемещения игроков и мобильный UX — следующие этапы. Произвольную телепортацию персонажа эксплойтом эта версия не предотвращает.
