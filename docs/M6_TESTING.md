# M6: проверка карты и контракта

База `1dc003b`, ветка `feat/m6-functional-mansion`, Draft PR в M5. План помещений и маршрутов: [M6_LEVEL_DESIGN](M6_LEVEL_DESIGN.md).

## Автоматические проверки

Восемь M0–M5 файлов `tests/{run,rounds,events,progression,persistence,reconnect,social,commerce}.luau` остаются без изменения: 1452 assertions. Дополнительно `luau tests/mansion.luau` проверяет декларацию, обязательные ID/типы, дубликаты, ошибочные границы/approach, лестницы, недостижимые комнаты, закрытый кабинет и независимый оконный путь, раздельные spawn, паузу и отмену таймера переноски. Compile всех `src/tests`, analyze pure-модулей/тестов, сборки и shipping audit задаёт `.github/workflows/check.yml`.

```sh
luau tests/mansion.luau
luau-analyze src/server/MansionLayout.luau src/server/WorldContract.luau tests/mansion.luau
rojo build default.project.json -o DoubleLife-M6.rbxlx
rojo build mansion-tests.project.json -o DoubleLife-M6-tests.rbxlx
python tests/check-build.py DoubleLife-M6.rbxlx
```

Валидация графа не заменяет реальную навигацию. Крупные изменения layout требуют следующего Studio-сценария. Исторические engine fixtures M2–M5 содержат координаты прежнего graybox; для их воспроизведения использовать соответствующий базовый commit, а для актуальной карты — M6 fixture. Они не объявляются пройденными на новой карте. Все прежние pure assertions выполняются на текущем коде, без ослабления.

## Studio: пеший сценарий

1. Открыть `DoubleLife-M6-tests.rbxlx`, выбрать Server & Clients, запустить **пять** клиентов. Не подключать Rojo к постороннему проекту и не включать доступ Studio к API.
2. Драйвер удерживает Waiting, пока идёт обход комнат. Первый клиент пешком посещает галерею, обе зоны обслуживания, второй этаж, террасу, мероприятия, читальню и выход; NPC несёт заказ в верхний архив. Проверяется отсутствие свободного navigation path в закрытый кабинет.
3. После обычного Countdown 12 с начинается первый раунд. Владелец меняет патруль и выдаёт пропуск; гость прикладывает его, входит, берёт экспонат и несёт вниз; персонал доставляет сок на второй этаж; шпион несёт ткань на террасу; агент проверяет следы. Гость участвует в музыке. Шпион самостоятельно открывает окно, входит, забирает досье, выходит через внутреннюю кнопку и пешком достигает экстракции. В лог записано фактическое время переноски.
4. После `M6 FIVE CLIENTS PASS` добавить клиентов до **8–15**. Обычный Results/reset и второй Countdown проверяют identity статической геометрии и уничтожение прежней round scope. Новый состав содержит двух шпионов и двух агентов.
5. Во втором раунде реликвия переносится из верхнего архива вниз; затем шпион забирает досье, владелец вызывает собрание через реальный prompt, большинство голосует, досмотр возвращает досье без устранения. Таймеры и NPC стоят в Council. Проверяется ходьба при выключенном свете, повторная NPC-доставка. Защитники выигрывают по настоящему 1200-секундному таймеру: ожидание не ускоряется, раз в 30 с выводится остаток.
6. После `M6 LARGE CLIENTS PASS` можно добавить клиентов до **12–15** в течение 180 с. Третий раунд проходит одновременный пеший подъём по двум маршрутам. `M6 LOAD PASS` фиксирует фактическое число клиентов. Пропуск этого этапа — NOT TESTED для большого лобби, основной PASS не означает 15-клиентную проверку.
7. После `M6 STUDIO SUITE PASS` проверить обычный first-person, H/J/K, видимость указателей и стандартные prompt-кнопки. Для ручного осмотра после автоматической Scriptable-камеры выполнить штатный Respawn: это очищает локальную прозрачность тела тестового драйвера и дополнительно проверяет безопасный spawn. По возможности включить Device Emulator для touch; gamepad требует фактического контроллера/доступного эмулятора. Завершить Test → End Session.

Драйвер применяет `Humanoid:MoveTo`, `PathfindingService`, настоящие `InputHoldBegin/End`, remotes и snapshots реальных клиентов. Он не меняет CFrame/Pivot персонажа. Его маршруты и NPC используют `AgentCanJump=false`: гладкие лестницы не требуют прыжка, а путь через верх перил не является маршрутом ходьбы. Обычный прыжок игрока не отключён; проверка отсутствия свободного пути к закрытому сейфу включает `AgentCanJump=true`. Штатные spawn/respawn/reset игры перемещают участников в обозначенные точки между раундами. Выбор ролей и места реликвии детерминирован для воспроизводимости. Blackout вызывается серверной fixture напрямую, чтобы проверить навигацию во время него; случайный гостевой триггер отдельно покрыт неизменными M3 pure-тестами. Это техническая интеграция, не ручная балансировка.

## Метрики и границы

Строки `M6 WALK` содержат wall-clock секунды и пройденное расстояние. `M6 METRICS` — Parts/Instances, время первого build/замены round-объектов, максимум полного rebuild и Heartbeat-интервала, количество ComputeAsync, отказов/тайм-аутов и прибытий двух NPC. Пик Heartbeat в локальном Studio с несколькими окнами не является измерением FPS мобильного устройства или production-сервера.

Провал навигации не лечится телепортацией NPC: две ограниченные попытки, отмена при смене scope/приказа и физический возврат. Бюджеты M6: патруль/проверка/возврат по 40 с; NPC-доставка/возврат до 45 с с сохранением TTL заказа 90 с. Игровые cooldown и индивидуальные награды прежние. Дверь/окно откладывают закрытие, пока персонаж/NPC физически занимает проём.

**real DataStore: NOT TESTED / paid shop: DISABLED.** Сохранения теста только в памяти; реальные платежи/production данные не используются. Release gate M4.1/M5 остаётся обязательным. Полные ручные матчи, экономика, финальный арт и релизная оптимизация — M7/M8.
