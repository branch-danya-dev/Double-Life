# Проверка M3

## Локальные и CI-проверки

Команды в README: исходные 46 M1 + 254 M2 assertions, отдельный `tests/events.luau` (87), компиляция всех файлов, анализ чистых policy/clock-модулей, production/test Rojo и `check-build.py`. GitHub Actions закрепляет Rojo 7.7.1 / Luau 0.745 и проверяет SHA256. Модули правил и будущие XP-hooks только в ServerScriptService; тестовый драйвер исключён из production.

## Автоматическая интеграция в реальном Studio

1. Собрать `rojo build studio-tests.project.json -o DoubleLife-M3-tests.rbxlx`. Открыть файл в Studio, F7 — Server and Clients, **сначала добавить только одного клиента**.
2. Runner проверит Waiting: картина → заказ → настоящая NPC-доставка → колокольчик/проверка охраны. Ждать **`M3 WAITING PASS: add FOUR clients now`**, затем добавить ещё **4** клиента в течение 240 с. Не управлять тестовыми персонажами во время Runner.
3. При трёх подключениях начинается обычный Countdown; четыре новых клиента должны подключиться до его окончания. Далее идут пять приватных ролей, отказы в запуске чужой ролью/без удержания у пульта, Relic и ограниченное внимание охраны, отсутствие гостевого триггера у шпиона, три разных действия гостя и задержанный Blackout. Выбор вида инцидента закреплён **только в серверном тесте**; production использует Random.
4. Во время поиска и сбоя света проводится обычное 25-секундное Council: сроки сохраняются, сброс реликвии и награды запрещены. После продолжения тестовый носитель отключается; реликвия возвращается в доступное место. Другой игрок поднимает/роняет её, физически несёт к постаменту; награда 15 выдаётся один раз. Проверяются 55-секундный cooldown и точное восстановление света.
5. На **`M3 LATE READY: add ONE client now`** добавить одного клиента в течение 240 с. Он наблюдает, не получает роль, не запускает события и не прогрессирует. Четыре исходных участника продолжают матч.
6. После перерыва владелец запускает Music. Клиентский тестовый драйвер физически двигает Humanoid на площадке и останавливает его по собственному публичному снимку; очки считает production-сервер по позиции. Три верные остановки дают 11 очков. Шпион крадёт досье во время мини-игры; владелец отключается, мини-игра доходит до конца. Шпион затем выносит досье; итог один.
7. Следующий раунд включает прежнего позднего клиента. Гость запускает Inspection; проверяется реальное движение охранника. Во время нового Relic носитель умирает и возрождается, предмет остаётся доступным. Собрание большинства досматривает шпиона. Таймер победы защитников сокращается до секунды — только этот терминальный шаг ускорен. Results отменяет незавершённое мероприятие; следующий раунд получает чистые таблицы, мир и освещение. Старый SessionClock не исполняет callback.
8. Ждать **`M3 STUDIO SUITE PASS`**. На момент окончания остаются 4 клиента: два исходных были намеренно отключены, один поздний добавлен. Сохранить только игровые маркеры, без посторонних логов/данных приложений. При `M3 STUDIO SUITE FAIL` прогон не считается успешным.

В тесте используются настоящие локальные клиенты, ProximityPrompt:InputHoldBegin/End и production RemoteEvent. Танец и доставка идут через Humanoid. Некоторые переходы игроков переставляются для проверки сценариев. NPC не телепортируются внутри раунда. Сроки объявления/поиска/музыки/cooldown/инцидента/Council — production, без подмены на короткие. Это автоматическая интеграция, **не ручное прохождение**.

Старая M2-сцена сохранена: `rojo build m2-tests.project.json -o DoubleLife-M2-regression.rbxlx`; её процедура описана в историческом M2_TESTING.md. Запуск двух серверных Runner в одной сцене не поддерживается.

## Дополнительные сценарии и будущая ручная приёмка

- Выбрать обе активности живым владельцем; проверить причины отказа, задержку 5 с, лимит 2 и перерыв 55 с. Отойти от пульта после открытия меню: запуск должен отклониться. Старый roundId, повторная доставка, поддельный результат мини-игры не дают очков; отдельного RemoteEvent «начислить результат» нет.
- В поиске проверить все три места: запад холла, восточная галерея холла, рядом с фойе. Предмет остаётся видимым на носителе; G/смерть/уход возвращают его на ближайшую доступную точку, а не за окно/в стену. Кража досье независима от переноса реликвии.
- На площадке можно участвовать любой ролью, войти/выйти, ошибиться и продолжить собственные цели. Вход только во время «замри» не засчитывает предшествующее движение. В Council движение и сроки стоят; после паузы конкурс продолжается.
- Повтор одной картины не накапливает гостевой триггер. Порядок/эффект нейтральных действий одинаков для всех ролей; скрытая проверка настоящего Guest только на сервере. У гостя возможна лишь нейтральная личная обратная связь, а происхождение инцидента отсутствует в снимках всех клиентов.
- Если охрана занята, мероприятие запрашивает внимание не дольше 10 с, а Inspection ждёт возможности только в пределах собственных 25 с. Старые GuardPolicy-ограничения сохраняются; нельзя гарантированно увести охрану от кабинета. Проверить возврат к обычному маршруту и обслуживание NPC.
- При Waiting 1–2 игрока могут повторять практику после завершения/тайм-аута. Уже осмотренная картина снова подходит для практики, но не удваивает цель раунда. При Countdown практика исчезает и сроки замораживаются; при отмене Countdown создаётся новая практика, без наград/ролей.
- Финальная человеческая приёмка после сборки игры: полный матч WASD, субъективный интерес, баланс 7 минут/награды/маршруты, разные размеры экрана, мобильное управление, реальные задержки сети, возвращение через закрывшееся окно. Эти пункты по договорённости не блокируют M3/M4.
